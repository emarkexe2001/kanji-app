## ADJ3 – Card slides (PR #48)
Decided with an interactive mockup (all suggested options approved):
- **Speed:** each slide takes 400ms. When several cards move, each starts 90ms after the one before.
- **Shuffled out:** a card that leaves the deck shrinks and slides up into the "Shuffled out (N)" button, fading to 20%. This replaces the old downward slide; the new card still drops on.
- **Hidden cards:** cards that leave from inside the deck (lowering the card limit, or the extra cards when Shuffle In takes several) peel off the back of the deck as blank cards.
- **Count:** "Shuffled out (N)" changes as each card lands, with a small bump. The deck, list and saving change straight away.
- **Add Back Cards:** the picked cards slide out of the open panel and grow into the deck card. The panel closes only after the last card has left it.
- **Pressing during a slide:** any click, tap, key, wheel/touch scroll or resize lands every card at once, then the press runs.
- **Scrolled page:** if the header is off screen, the card still slides up out of the top of the window towards the button.
- **Reduced motion:** nothing slides; the slides are hidden from screen readers.
- **Next (added by the user mid-PR):** the card slides in from the right, the mirror of Back (same 260ms). The first card on page load and after a deck switch still deals up from below.
- **Tests:** UI tests 237 → 290, web unit tests 35 → 39. Every break-and-restore check turned tests red.
- **Review:** no must-fix items. All four should-fix items were done before merging: missing tests, landing on scroll/resize, the "New" ribbon flicker, and a guard test.
- **Browser check:** the agent used headless Chrome; the user checked it in a real browser before merging.

## ADJ2_5 – Floating panel fixes (PRs #50, #52)
Decided with a mockup, then a corrected one:
- **Overlap (Option A):** the 300px panel floats beside the deck only from **1100px** (18px gap). From 1024px to 1099px it is the phone-style pop-up with the deck below it. The 1100px breakpoint is defined once for code and styles, with a test that checks they match.
- **Phone fit (Option 1, then the slim card):** below 1100px the pop-up is a fixed 260px tall, so picking a card doesn't move the deck. While it is open, the deck card is a "slim card": no Reading Breakdown and no fanned backs. The ★ Common Word badge and "Full Word Meaning" label are hidden from view but still read by screen readers. The meaning is one line ending in "…". At 360×640 Deck Shuffle ends at 624px, with 16px to spare.
- **Panel top:** measured from the header, so zoom or a title on three lines can't make it cover "Shuffled out (N)".
- **Clicks:** a press dragged out of the panel no longer swallows the next click outside.
- **Also fixed:** the deck card used to end up about 15px under the panel while it slid open.
- **Accepted as is:** on a phone turned sideways (640×360) the panel covers the deck. On a tablet it covers the end of the Deck picker, with a gap above the deck card.
- **Tests:** UI tests 290 → 333 in #50, and 334 with #52. All 13 break-and-restore checks turned tests red.
- **Review:** no must-fix items. Two should-fix items went into #52 (a stronger no-grow test, and one wide-layout source) because #50 was merged after the user's browser check, before they were pushed.

## Process lessons
- **The ADJ2_5 phone mockup was wrong.** It drew the deck card 112px tall, but the real card is 175px (Common badge, "Full Word Meaning" label, fanned backs and padding), so the agreed fit left Deck Shuffle 55px below the screen. The agent stopped and asked, and real-app screenshots were approved as a corrected mockup. Mockups for fit questions should now be measured from the real app, using the longest real content.
- **Mockups can find questions the ticket missed.** Reading the code before the ADJ3 mockup showed two undecided behaviours.
- **When a shared value changes, list everything that uses it.** Changing Next's slide also changed the first card on load and after a deck switch, which the agent spotted and asked about.
- **A browser re-check caught a fix that broke slides.** Landing cards on every scroll event cut slides short, because Chrome fires scroll events itself. The cards now land only on wheel, touch and resize.
- **PR #50 was merged before two small review fixes were pushed.** They went into follow-up PR #52. When asking which fixes to do, say in chat that the PR must wait for them.
- **The Chrome extension wasn't connected,** so both agents used headless Chrome. The user did the real-browser checks.
- **Memory ran low,** so a dev server was stopped. Reviews read the code, and CI ran the full test suite.
- **Avoid "work in progress" in commit titles.** One reached main in #50.
