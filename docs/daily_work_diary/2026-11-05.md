## TEST6 – Slow UI tests (PR #67)
- **Cause, measured:** after every click or key press, user-event waits for the next turn of the event loop. On Windows each wait is about 12ms, and longer on a busy machine, so tests with many actions crept up to the 5-second limit.
- **Fix:** a `NO_PAUSE` option in `helpers.tsx`. The same events still fire in the same order; only the pauses between them go. A click went from 67ms to 26ms. Tests that walked the deck twice were split into two tests that walk it once.
- **Results in full runs:**
  - Back "last 50 cards": 4.7–5.0s → 0.5–0.7s
  - N5 deck: 4.3–4.5s → 1.1–1.5s
  - adding a card back: 4.3–4.4s → two tests of 2.0–2.7s
  - Deck Shuffle: only a little faster
- **Gap found:** break-and-restore showed the "last 50 cards" test also passed with 49. A new test checks exactly 50.
- **Scope change (agreed):** two more tests timed out in the first repeat runs, so they were fixed here too.
- **Repeat script:** `npm run test:ui:repeat` runs the UI tests several times in a row.
- **Follow-up:** the slow tests still left are listed in TEST8.

## Process lessons (TEST6 retro)
- **Write follow-up tickets once, after the final runs.** TEST8 was rewritten 4 times.
- **Do the final check with the script the PR ships** (`test:ui:repeat`), not manual runs.
- **Use the same number of runs before and after.**
- **Keep the PR Summary to one screen,** with big tables in `<details>`.
- **Call a commit "final" only if it is the last one.**
- **Check facts before stating them when dropping a review nit,** or say "not checked".
- **The full test run is slow,** so a scope change mid-PR costs about an hour of re-runs.
