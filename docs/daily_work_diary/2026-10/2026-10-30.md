## TEST2 – Test folder structure (PRs #54, #56)
- **Moved:** the four unit tests in `src/` moved to `apps/web/test/unit/` and `packages/core/test/unit/` with `git mv`, so their history follows. Only their imports changed.
- **Found by pattern:** every test script now uses a quoted pattern (e.g. `"test/unit/**/*.test.ts"`), which Node's test runner expands itself. Unquoted, Linux CI would have skipped nested files (39 tests found instead of 41).
- **Type-checked:** before this, no test file was type-checked. Each workspace now has a `test/tsconfig.json`, and `typecheck` runs both. It adds `@types/node`, so the PR said to run `npm install` after merging.
- **Ticket move:** the agent was told not to move the ticket, which went against the "move finished tickets" rule, so it needed a follow-up PR (#56).
- **Flaky test found:** "pressing Shuffle In Cards again and again" in `card-slides.test.tsx` failed about 1 run in 10, on `main` too. It became TEST5 (#55).

## FEAT5 – Colour mode menu and Dark mode (PRs #57, #58)
Decided with a mockup, approved on 2026-10-30:
- **Header (option B):** two rows. The colour mode button is top left, "Shuffled out (N)" top right, and the title has its own row.
- **Mode button and menu:** sun + "Light ▾" or moon + "Dark ▾". The menu switches the mode straight away and works fully by keyboard.
- **Dark = slate:** page `#0f172a`, cards `#1e293b`, with brighter reading colours. All Dark text pairs are at least 4.5:1.
- **Light is exactly as before:** each Light colour is checked against the Tailwind colour it replaced.
- **No flash:** a small script in `index.html` sets the mode before the first paint.
- **Built for more modes:** colours are per-mode tokens in `@kanji/core`, so FEAT5_5 (high contrast) can add a mode without changing components.
- **Phone fit:** at 360×640 with the Shuffled-out pop-up open, Deck Shuffle now ends at 640px exactly, with no room to spare.
- **Tests:** UI tests 334 → 409, `@kanji/core` 10 → 20.
- **Review:** four review fixes went in before merging: testing.md wording, Tailwind version ranges, deck keys ignored while the mode menu is open, and the script-ordering test. The user's real-browser check passed.
- **Split:** the first-visit start page (two preview tiles, following the device colours until a mode is chosen) became FEAT5_1.

## Process lessons
- **Measure the real app before drawing a mockup.** A headless Chrome script found the header-fit problem before the mockup was drawn.
- **A dev server left running for the user's check locked `node_modules`** and broke the agent's `npm ci`. Tell agents which port is in use, or stop the server before resuming them.
- **Check reviewer claims against the PR.** The reviewer twice said evidence was missing when it was in the PR body.
- **When a PR adds a dependency,** put an "after merging, run `npm install`" note at the top of the PR.
- **Old tickets can be partly done already,** so check what's left before briefing an agent.
- **Update `docs/testing.md` in the same commit as the test it describes.**
