## FEAT5_1 – Colour mode start page (PR #60)
- **What it does:** until a mode is saved, the app opens on "Choose how the app looks", with Light and Dark tiles. Choosing one saves it and shows the cards in that mode.
- **Dark-device fix:** when nothing usable is saved, `index.html` and the app now follow the device's light or dark setting. Before, they always opened in Light.
- **Flow:** a mockup agent measured the real app and wrote a UI handover. A feature agent built it, a test agent wrote the tests, and a review agent checked it against the spec.
- **Tests:** UI tests 409 → 481. `test/setup.ts` now saves Light before each test, so the existing tests still open on the cards. First-visit tests opt out with `firstVisit()`. The 13 tests of the old FEAT5 rule were rewritten, as this ticket changes that rule.
- **Browser check:** the feature code with the old tests failed 362 tests, which the shared setup change fixed. A late bug fix meant re-running the browser check on the final commit.

## Process changes (PRs #62, #64, #66)
- **In-person check (#62, standards 5.4):** every UI pull request gets a person to use it in a real browser and check it against the ticket, the agreed answers and the mockup. An agent's headless check no longer counts on its own. The PR stays a draft until the check passes.
- **PR template (#64, PROC1):** every PR lists its ticket and ticks off each test scenario with the test that covers it. Includes sections for test counts, break-and-restore, the browser check and the in-person check. 21 scripts tests check the template.
- **Ticket clarification step (#66, PROC3):** before starting, read the ticket against the standards. Write any questions in the ticket's Questions / Clarifications section, with each agreed answer and its date. Agreed answers need tests, like test scenarios. The minimum deck size is now 1 card, matching the app.

## Decisions made today
- **The four-agent flow is the default for every ticket:** a mockup agent, a feature agent, a test agent and a review agent with handovers between them, then an in-person check and a PR retro agent after merging.
- **Docs and process tickets use a lighter flow:** one agent makes the change and its tests, then a separate review agent, then the retro.
- **UI pull requests need an in-person check** (standards 5.4).
- **Minimum deck size is 1 card** (standards 4.2).

## Process lessons
- **The exact UI handover worked:** FEAT5_1 needed no rework from the mockup.
- **A bug fix after the test agent finished** left the counts, PR body and break-and-restore rows out of date. Bug write-ups now get an "after the fix" checklist with an owner.
- **Post review findings and their outcomes as a PR comment,** so a new session can see the review was handled. The handovers had only been in a scratchpad.
- **Cite code snippets in break-and-restore, not line numbers,** which go stale after later fixes.
- **Pass review fixes on in order,** feature agent first and then the test agent, so they don't push over each other.
- **Build the PR checklist only from the ticket's own sections,** and label anything extra as an addition.
- **Put manual checks that happen after merging in the diary,** so they get followed up. PROC1's: check that a new PR is pre-filled from the template.
