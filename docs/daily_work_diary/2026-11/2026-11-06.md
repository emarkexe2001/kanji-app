## TEST4 – Saved-choice test (PR #70)
- **Cause (the test):** the old test changed the saved choice while the app was still open. On a busy machine, the app's own save of what it had loaded ran when the test closed the app, and wrote the old ticks over the test's value.
- **Proof:**
  - **Natural:** failed once in 30 runs on `main`.
  - **Forced:** a test-only mock made React's scheduler pause after every task, as on a busy machine. The old test failed 20 of 20, and the new tests passed 20 of 20.
- **Fix:** split into three tests, each saving its choice before the app opens. No app code changed. `docs/testing.md` now says to save values before the app opens.
- **Also:** "a card in two ticked decks…" went from about 3.5s to about 2.7s with `NO_PAUSE`, with its own 15-second limit.
- **Review:** one should-fix (also check the colour-mode test files), done before merging.

## TEST5 – "Shuffle In Cards again and again" (PR #72)
- **Cause (the test):** Shuffle In only leaves out cards already in the deck. So the third press could draw a card an earlier press had shuffled in and back out. That card went back into the deck, and the count rightly stayed at 2. The ticket's guess (the `landNext()` helper) was checked and ruled out.
- **Proof:**
  - **Natural:** failed 4 times in 52 runs.
  - **Forced (`Math.random` fixed at 0):** the old test failed 10 of 10, and the fixed test passed 10 of 10.
- **Fix:** the test now chooses which card each press draws, and checks it's a fresh card. A new test covers a shuffled-out card coming back. No app code changed.
- **Checks:** the file passed 50 of 50 repeat runs.
- **Review:** one should-fix (the test counts table had two rows swapped), fixed in the PR description.

## Process lessons
- **The summary sections of PR descriptions were still long,** both in TEST4's PR and in TEST5's. Keep them to about 6 short lines, and put every table and checklist in `<details>`.
- **When dropping a review nit, give the real reason,** not just "repo convention".
- **Once the cause is found, add a "Cause found" line to the ticket's Origin,** so a wrong guess isn't left standing.
- **Copy test counts from the test run output,** never type them by hand.
- **After the first failure, add logging before looping more runs.** TEST5 spent about an hour on repeat runs before a log of the animations showed the cause.
- **Re-run a red CI job before blaming the PR.** PR #71 failed on the TEST5 flaky test, which it couldn't affect. The slow tests listed in TEST8 can still time out.
- **A CI change can't be proved docs-only from a branch built on it,** because that branch carries the code changes too. CI2 used a throwaway base branch. Say up front in a CI ticket how each scenario will be proved in real CI.
- **Never skip the commit hooks (`--no-verify`) without asking first.** CI2's agent used it once on the throwaway branch to push a bad commit message for the proof. The scenario was approved, but the flag wasn't asked about.
- **CI2 retro:** about 70 minutes, most of it on proof runs, the question and waiting to merge. The code took minutes.
