## PROC5 – Move tickets only after their PR merges (PRs #83, #85, #87)
- **Rule (user, 2026-11-11, FEAT5 retro):** a ticket isn't complete until its PR is merged. It then moves with `git mv` in a separate follow-up `docs/` PR, with `Completed On: <merge date> (PR #n)`. The ticket's own PR never moves it.
- **Check before every new task:** compare every open ticket with the merged PRs. One follow-up PR moves every finished ticket, one commit per ticket. It also edits each merged PR's Ticket link (`gh pr edit`) to point to `completed_tickets/<type>/`.
- Standards 5.4 and 5.6 and the PR template now say this. The template's Ticket link points to the open folder, and its §5 box asks that the ticket is not moved.
- **Tests:** scripts tests went from 128 to 145, and all 18 break-and-restore checks turned tests red. One break showed the old-wording check missed "their own pull request", and that was fixed before review.
- **Review:** no must-fix. Two should-fix fixes went into the PR description: a shorter Summary and a tidier checklist. The user agreed to the builder's three choices.
- **Retro:** clean. All TEST7 retro actions were done. No old-rule wording is left on main.
- The first moves under the new rule were TEST7 (#84) and PROC5 (#87).

## Process lessons
- **The FEAT5 ticket stayed open for 12 days** because its move was put off with no owner. The sweep before each task now catches this.
- **A sweep made before another ticket's PR merges won't catch that ticket.** Run the sweep again right after each merge (PROC5 was missed by #84 and needed #87).
- **Keep the PR Summary to about 6 short lines, one idea per bullet.** TEST7 still had 7 long bullets. PROC5 got it right after review.
- **Post review outcomes (R# → result) as a PR comment** after the fixes, not only in the PR body.
- **When a ticket adds a convention, write the rule where agents will read it** (CHORE4's diary month folders went into no doc).
- **Break-and-restore keeps finding real gaps:** FEAT5_5's Clear List test passed on the bug, and PROC5's old-wording check missed a phrase.
