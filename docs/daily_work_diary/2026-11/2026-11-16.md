## Process and tooling
- **Refactor review routine:** a cloud agent reviews the whole code base on the 1st and 15th of each month at 09:00 UTC. It opens a docs PR adding `docs/refactor_reviews/YYYY-MM/YYYY-MM-DD.md` and never changes code or writes tickets. The first run is 2026-12-01.
- **Push-slip retro (standards 5.4, PR #100):** pushes to a PR's branch are now gated on the PR being open, and follow-ups go on a new branch once a PR is ready to merge.
- **Each "Do not merge yet" comment is now edited** when the PR is ready, instead of adding a second comment.

## Process lessons
- **I pushed to a merged PR's branch.** A follow-up commit went to PR #92's branch after it merged, which recreated the deleted branch. My state check printed MERGED but didn't stop the push. It was fixed via PR #94, and led to the standards 5.4 rules.
- **An agent and I used the same folder at once.** I ran a ticket sweep agent in the main checkout while making a branch there. Its `git checkout main` moved my commit onto local main, and the push to main was refused by branch protection. Nothing reached GitHub's main. Now: no git work in a folder an agent is using, and pushes name the branch.
- **Count before agreeing a size rule** (CHORE6). **Check the code before agreeing a behaviour answer** (CHORE8): one throwaway test per case would have caught answer 4's wrong assumption.
- **Cap flake loops** at one round on the branch and one on main (CHORE7).
- **"Nothing changes on screen" proofs work well:** class-list diffs, seeded screenshots and built-CSS comparison. The scripts can be reused for CHORE9 and CHORE10.
